Reports @Page route overrides and @file:PackageMapping values that Kobweb rejects when building your site, or that it accepts but are probably mistakes.

Kobweb would fail the build for:

  • route overrides which put an inferred ({}), catch-all ({...}), or optional ({?}) dynamic segment anywhere but at the end
  • pages that live outside the pages package (unless they specify an absolute path)
  • routes that start with api, which it reserves to avoid conflicts with backend API routes
  • malformed dynamic segments, empty segments, and . or .. segments (which browsers remove from URLs)
  • routes that use the same dynamic segment name more than once, as only one of the values can be read
  • characters that can't be part of a URL path as written, such as spaces and non-ASCII characters (which should be percent-encoded instead, e.g. about%20us)
  • package mappings with a catch-all or optional dynamic segment, as a package is never at the end of a route (or with an inferred one anywhere but at the end)
It accepts these but still shows a warning for them, as they're probably mistakes:
  • package mappings that contain more than one segment

// pages/users/Posts.kt
@Page("{}/posts")   // Inferred segment isn't at the end
@Page("{post")      // Malformed dynamic segment
@Page("{rest...}")  // Malformed too, as a catch-all's "..." goes at the start
@Page("a//b")       // Empty segment
@Page("../posts")   // Browsers remove ".." from URLs
@Page("{id}/{id}")  // Only one of the "id" values can be read
@Page("about us")   // Space (use "about-us" or "about%20us" instead)

// pages/team/PackageMapping.kt
@file:PackageMapping("our/team")  // More than one segment
